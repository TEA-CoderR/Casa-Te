## 1. 结论

**界面：** 已经是一套统一、有自己识别度的设计（深绿顶栏 + 柠檬绿会员/订单 + 白色内容），放在意大利区域零售商的 App 里属于中上水平。离顶级 App 还差的主要不是"好不好看"，而是下面四件事。

**能不能给顾客用：** 现在适合内部测试和员工试用，**还不适合公开上线**。原因大多不在界面：

| 方面 | 现状 | 判断 |
|---|---|---|
| 视觉统一、品牌感 | v1、v2 做完后一致 | 达标 |
| 主流程（逛 → 加购 → 结账 → 取货 → 退货） | 都能走通，结账只有一页 | 达标 |
| 搜索 | "detersivo piatti""sciampo"都是 0 结果 | **不足，上线前必须改** |
| 商品内容 | 11,494 件上架：描述 0 件，有品牌的 337 件；名称里带供应商编码 | **不足** |
| 通知 | 只有邮件，没有推送；邮件内容很简单 | **不足** |
| 稳定性保障 | 没有崩溃监控、没有错误兜底页、没有强制升级 | **不足，上线前必须补** |
| 运营环境 | 只有测试库、Stripe 测试模式、发信域名未配、法律文本未审 | **不足（非代码）** |
| 库存准确度 | ERP 每天 07:00 同步一次 | 有风险 |
| iOS | 没有构建流程，App Store 未配置 | 缺失 |
| 原生细节（触感反馈、启动画面、列表性能） | 基本没有 | 离顶级有差距 |

按第 5 节的顺序做完"上线必须"部分，再完成 `LAUNCH_CHECKLIST.md` 里的业务和法律项目，就可以先对员工和会员小范围开放（一家门店、只做到店取货）。

## 3. 上线必须（代码部分）

### L1. 搜索质量

现状（`search_products`，`20261103125122_search_ranking.sql`）：每个词必须是"名称 + 品牌 + 编码 + 条码"的子串。不含分类名，不容错。
实测：`detersivo piatti` → 0；`sciampo` → 0；`dentifrici` → 23（碰巧是子串）。

改法（新迁移）：
1. `products.search_text` 加入所属分类和上级分类的名称（生成列不能跨表：改成普通列 + 触发器，分类改名时一并更新）。
2. 新表 `search_synonyms(term text primary key, expands_to text)`，后台可维护；先放一小批常见说法（sciampo→shampoo，scottex→carta cucina 这类由老板提供，**不要自己编一长串**）。RLS：所有人可读，只有 staff 可写；显式 GRANT。
3. 严格匹配结果少于 6 条时，追加模糊匹配（`pg_trgm` 的 `word_similarity`，阈值先取 0.45，在测试里固定下来），排在严格结果后面。
4. 结果仍然"有货在前"。

界面（`app/(tabs)/catalog.tsx` 搜索态）：
- 模糊结果上方一行灰字："Risultati simili a "sciampo""。
- 0 结果页：保留现在的标题，下面加"Esplora per reparto"（就是搜索空态那张列表）和一个"Offerte Soci"入口，不要只剩一个"Nuova ricerca"按钮。
- 搜索空态：有最近搜索时显示在"Esplora per reparto"上面（`recent` 已有）。

验收：`tests/db` 新增用例——`detersivo piatti`、`sciampo`、`carta igenica`（少一个 i）都返回 ≥1 条相关商品；`npm test` 通过。

### L2. 推送通知（需要新的原生包）

- 依赖：`expo-notifications`（安卓走 FCM）。
- 新表 `push_tokens(user_id, token, platform, updated_at)`，RLS 只允许本人读写，显式 GRANT。
- 发送：在 `notify-order-event` 里，和邮件同一个事件触发，调用 Expo Push API。函数保持"只用 fetch、无 SDK"。
- 发哪些：订单可取货（最重要）、订单被取消或退款、退货申请有答复。**不发营销推送**（那需要单独的同意，【法务】）。
- 什么时候问权限：第一次付款成功的页面上，放一张卡片"Ti avvisiamo quando l'ordine è pronto" + 按钮"Attiva le notifiche"。不要一打开 App 就弹系统权限框。
- 点通知 → 打开对应订单页（`casate://order/<id>`）。
- Profilo → Account 加一行"Notifiche"，可关。

### L3. 交易邮件

现状：一句话的纯文字邮件。订单确认邮件里没有商品清单。
改法（`notify-order-event/handler.ts`，仍然纯字符串模板）：
- **确认邮件**：订单号、商品清单（名称、数量、单价、小计）、会员优惠、合计、取货门店的地址和营业时间、"取货时出示订单号或 App 里的条码"、卖方公司信息（从 `companies` 读）、退货说明链接。【法务】确认这封邮件是否满足"在耐久介质上确认合同"的要求。
- **可取货邮件**：门店地址、营业时间、地图链接、保留到哪一天。
- 统一的品牌头尾（深绿条 + 标志文字，不用远程图片也能看）。
- 单元测试覆盖每种邮件的生成。

### L4. 错误兜底与监控

- `app/_layout.tsx` 导出 `ErrorBoundary`（expo-router 支持）：页面出错时显示"Qualcosa è andato storto" + "Riprova" + "Torna alla home"，不要白屏。
- 崩溃上报：接入 Sentry（`@sentry/react-native`，需要新的原生包；DSN 用环境变量，**不要写进仓库**）。只上报错误，不上报个人数据；关闭会话回放。【法务】在隐私政策里补一句。
- Edge Function 出错和 Stripe webhook 失败要有告警（`LAUNCH_CHECKLIST` 已列）。

### L5. 强制升级与维护开关

Supabase 地址是编进 App 的，旧版本可能调用已经改掉的函数。
- `app_settings` 加 `min_app_version text`、`maintenance_message text`（新迁移）。
- App 启动时读取：版本低于 `min_app_version` → 全屏"Aggiorna l'app"（按钮打开商店页）；`maintenance_message` 非空 → 全屏提示，不能下单。
- 后台 Settings 页可改。

### L6. 启动画面与首屏

- 配置 `expo-splash-screen`：深绿底（`colors.band`）+ 居中的柠檬绿标志，和欢迎页衔接。现在字体加载完之前是白屏。
- `app.json` 的 `ios.supportsTablet` 暂时设为 `false`（平板布局没有设计过）。

### L7. 库存新鲜度

现状：`同步.bat` 每天 07:00 跑一次。白天门店卖掉的货，网上仍显示有货，拣货时才发现缺货。
- 把定时任务改成营业时间内每小时一次（`设置每日定时同步.bat` 加重复间隔；电脑上的文件用 stage/commit 更新）。先确认一次同步要多久、对 ERP 数据库有没有压力（只读查询）。
- 【老板】是否设"安全库存"：例如门店只剩 1–2 件的商品，网上不显示有货。要改的话在 SQL 的可售数量里减去缓冲值，客户端不动。

### L8. 字体放大与无障碍

- 安卓系统字体调大时，票据、标签、底部栏这些固定高度的地方会撑破。全局给 `Text` 和 `TextInput` 设 `maxFontSizeMultiplier = 1.3`（在根布局里设默认值），然后在 1.3 倍下把主要页面过一遍。
- 可点区域不小于 44×44：检查商品卡的心形、数量加减、标签页。
- TalkBack 走一遍主流程：每个按钮有名字，价格读作"3 euro e 29"。

### L9. 商品图缩略图（性能）

商品卡里 120 像素宽的图，实际下载的是 800–1500 像素的原图（约 74 KB 一张）。一屏 40 件商品约 3 MB，用流量的顾客会觉得慢。
- 图片服务器生成缩略图（例如 `…/01_t.webp`，320 像素宽），列表和卡片用缩略图，商品页用原图。
- 这需要动图片服务器（`img.casaete.top`）。**先问老板谁能操作服务器**，不要自己去连。

## 4. 向顶级 App 靠拢（体验升级）

### X1. 取货时间承诺 【老板】
顶级的到店取货 App 都会告诉顾客"什么时候能取"。现在只写"ti avvisiamo quando è pronto"。
- 老板定一个规则，例如"营业时间内下单，2 小时内备好；18:00 后下单，次日 10:00 前备好"。
- 定了以后：购物车门店卡、结账页取货行、付款成功页、确认邮件都显示"Pronto entro le 16:30"这样的具体时间。计算放在 SQL（`quote_cart` 返回），客户端只显示。

### X2. 付款方式 【老板】
- Apple Pay / Google Pay：Stripe Checkout 页面本身支持，在 Stripe 后台打开即可，不用改代码。打开后把按钮文字从"Paga €7,66 con carta"改成"Paga €7,66"。
- PayPal、Satispay：如果 Stripe 账户支持，同样在后台开。
- "到店付款"：意大利的到店取货很常见。风险是不来取。【老板】决定要不要。

### X3. 相机扫条码（需要新的原生包）
- `expo-camera` 的条码识别。入口就是首页搜索框右边那个图标。
- 扫到 → 直接打开商品页；没找到 → "Prodotto non trovato" + 手动输入。
- 在店里的用法：扫货架上的商品看会员价、加入收藏。这是实体零售 App 最有用的功能之一。

### X4. 列表：无限滚动 + 虚拟化
现状：`ScrollView` 里一次画出全部商品，底部一个"Mostra altri prodotti"按钮，每页 40 件。
- 商品列表、搜索结果、Offerte Soci 改用 `FlatList`（两列），滑到底自动加载下一页，底部显示加载骨架。
- 保留"回到顶部"的习惯：点当前标签回顶。
- 验收：787 件的 Offerte Soci 列表连续下滑不卡顿（真机）。

### X5. 触感与微动效（需要新的原生包）
`expo-haptics`：加入购物车、数量加减、收藏、下拉刷新触发、付款成功、会员卡条码弹出，各用一次轻触感。不要每个按钮都震。

### X6. 结账页
- 会员在合计上方加一行："Con i Prezzi Soci risparmi €1,20"（金额来自报价，已有 `memberSaved`）。
- 合计区常驻显示三行：Prodotti / Ritiro in negozio · Gratis / Totale，不需要展开"4 articoli"才看到。
- 未登录点结账：现在是整页"Accedi per completare l'ordine"。改成在这页直接输邮箱 → 收验证码 → 回到结账（沿用现有的验证码登录），不要把人带离结账流程。

### X7. 会员卡出示
弹出大条码时：屏幕亮度调到最高、保持常亮（`expo-brightness`、`expo-keep-awake`），关闭后恢复。Lidl Plus 这类 App 都这样做，收银台扫码成功率高很多。

### X8. 客服与帮助
- Profilo → Assistenza 加"Domande frequenti"页：怎么取货、多久备好、怎么退货、会员价怎么算（内容【老板】提供或确认）。
- 加一行"Contattaci"（邮箱）；【老板】如果有 WhatsApp 客服号，加"Scrivici su WhatsApp"。

### X9. 登录页与欢迎页统一
欢迎页（`benvenuto`）是深绿整页；登录首页是白底 + 另一种绿色的标志牌。两个页面前后脚出现，像两个 App。
- 登录首页（`step === 'welcome'`）改成和欢迎页同一个深绿底、同一个标志、同样的白色主按钮；表单页保持白底。
- 登录表单的输入框（占位文字当标签、圆角 8）和 App 里其他表单（标签在上、`TextField`）统一成 `TextField`。
- 【老板】是否加"Continua con Google"。注意：iOS 上只要提供第三方登录，就必须同时提供 Apple 登录。

### X10. 商品名称清理
列表里能看到："Arix Spugna Aqua Massage C/ANT. 2PZA56002""Cesta Oval 49*36*55 Yd-13200low-Hea""Cesta Elegance Bianco58x38x28h - 35 l""Ace Gentile 2,3 l PROF.LAVAND.MUSCH.C1913"。
- 扩展 `clean_product_name`（原名保留在 `erp_name`）：去掉结尾的供应商编码；尺寸写成"58×38×28 cm"；字母和数字之间补空格。
- 先出一份"改前 / 改后"对照表（至少 200 条抽样）给老板看，确认规则后再批量应用。**只改格式，不改含义。**

### X11. 网页版的标题与分享
现在所有页面的浏览器标题都是"CASA & TE"，分享商品链接没有预览图。
- 每页设置标题（商品名、分类名）；商品页加 Open Graph 标签（名称、图片、价格）。
- 由于是单页应用，搜索引擎收录有限；要做收录需要改成静态导出，另行评估，不在这一轮。

### 可选，需要老板同意才做
- 首页加一栏"Compra di nuovo"（买过的商品）。日用品复购率高，这一栏通常是转化最好的；但老板说过首页先不动。
- 缺货商品"到货提醒"。
- 会员卡加入 Google 钱包。

## 6. 上线前验收脚本（真机，安卓至少两台不同尺寸）

1. 新装 → 欢迎页 → 注册 → 收到验证码邮件 → 进入首页。
2. 搜索"detersivo piatti" → 加购 3 件（含一件会员价）→ 入会 → 购物车价格变化 → 结账 → 付款 → 成功页 → 收到确认邮件（内容完整）。
3. 后台拣货 → 标记可取 → 手机收到推送 → 点开是这个订单 → 条码可扫 → 标记已取 → 订单进入"Completati"，页面文字正确。
4. 申请退货 → 后台批准 → 收到邮件和推送 → 退款。
5. 付款中途关闭 → 订单 31 分钟后过期 → 库存恢复。
6. 拣货时缺一件 → 部分退款 → 顾客看到的订单和邮件正确。
7. 断网打开每个标签页 → 都有提示和重试，不白屏。
8. 系统字体调到最大 → 主要页面不破版。
